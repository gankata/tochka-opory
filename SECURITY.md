# Безопасность

## Локальная модель и границы защиты

Приложение рассчитано на личный компьютер и доверенную домашнюю сеть. Production по умолчанию слушает только `127.0.0.1`. Не выставляйте HTTP-сервер напрямую в интернет и не используйте LAN-режим в публичных сетях: соединение компьютера и телефона не шифруется TLS.

Обычная SQLite-база, SQLite-копии и полный JSON-экспорт локально не зашифрованы. Используйте FileVault на macOS, BitLocker/Device Encryption на Windows и отдельную защищённую учётную запись ОС. Пароль приложения и шифрованный экспорт не заменяют шифрование диска и не защищают от человека или вредоносной программы, уже получивших доступ к вашей сессии ОС.

## Реализованные меры

- Локальный пароль хранится как scrypt-хеш с солью; ошибка входа не раскрывает, какая часть учётных данных неверна.
- После повторных неудачных попыток действует временная блокировка, а память счётчика попыток ограничена.
- Сессионные и API-токены хранятся как SHA-256-хеши; cookie сессии — HttpOnly и SameSite=Lax.
- Истёкшие сессии удаляются при создании новой; смена пароля завершает остальные сессии.
- Изменяющие API-запросы браузера проходят проверку Origin. Bearer API остаётся доступен для локальной автоматизации без Origin.
- Production использует Content Security Policy, запрет встраивания во фреймы, `nosniff`, строгий Referrer-Policy и ограниченный Permissions-Policy.
- Личные API-ответы получают `Cache-Control: no-store`; изображения заметок доступны только после аутентификации и проверки владельца.
- Размер тел запросов ограничен; сгенерированный HTML заметок очищается от опасной разметки.
- Стартовый код разбит на отдельные загружаемые части, а `npm run check:performance` предотвращает заметную регрессию начальной загрузки.

HSTS намеренно не применяется: приложение рассчитано на локальный HTTP, и такой заголовок мог бы помешать подключению телефона.

## Резервные копии

Автоматические SQLite-копии находятся в `data/backups/`. Держите дополнительную копию на отдельном зашифрованном носителе и периодически проверяйте восстановление. Копии на том же диске не защищают от отказа диска или потери компьютера.

## Публикация

Перед публикацией выполните `npm run check:public`. Каталог `data/`, SQLite-базы, резервные копии, журналы и файлы окружения не должны попадать в репозиторий. Не публикуйте JSON-архивы, экспорты и скриншоты с личными записями. Подробнее — в [PRIVACY.md](PRIVACY.md).

## Сообщение об уязвимости

До настройки публичного канала безопасности создайте приватное обращение владельцу репозитория. Не прикладывайте реальную базу, пароли, токены или личные записи. Для воспроизведения используйте только вымышленные данные.

## Reporting a vulnerability

Privately contact the repository owner. Do not attach real databases, passwords, tokens, exports, or personal records. Use fictional data only. The default local server is not designed for direct internet exposure.
